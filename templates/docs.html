Documentation

API reference

Create an order, show the QR or hosted page, and receive a signed webhook when the payment is confirmed.

Authentication

Get your key from the dashboard and send it as a bearer token.

Authorization: Bearer sk_live_xxxxxxxxxxxxxxxx

Create an order

POST {{ base }}/api/v1/orders

curl -X POST {{ base }}/api/v1/orders \
  -H "Authorization: Bearer sk_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 499,
    "order_ref": "user42-premium",
    "callback_url": "https://your-app.example.com/payment-webhook",
    "redirect_url": "https://t.me/yourbot",
    "expires_in": 900
  }'

Only amount (INR, max two decimals) is required. order_ref is your own reference; creating another pending order with the same order_ref and amount returns the existing one (HTTP 200) instead of a duplicate.

{
  "order_id": "ord_Ab3dE9xQz1k",
  "status": "pending",
  "amount": "499.00",
  "payable_amount": "499.00",
  "currency": "INR",
  "upi_link": "upi://pay?pa=you%40fam&pn=You&am=499.00&cu=INR&tn=...",
  "qr_url": "{{ base }}/qr/ord_Ab3dE9xQz1k.svg",
  "pay_url": "{{ base }}/pay/ord_Ab3dE9xQz1k",
  "expires_at": "2026-01-01T10:15:00+00:00",
  "created": true
}
Always show payable_amount. If another open order already holds the same amount, a few paise are added so each open order has a unique amount. Customers must pay exactly that figure; it is what makes automatic matching unambiguous.

Check status

GET {{ base }}/api/v1/orders/<order_id> — status is pending, paid or expired. Paid orders include utr and paid_at.

Webhooks

When a payment is matched we POST JSON to your callback_url (or the default in the dashboard). Respond with any 2xx status. Failed deliveries are retried up to 6 times with increasing delays.

{
  "event": "payment.success",
  "order_id": "ord_Ab3dE9xQz1k",
  "order_ref": "user42-premium",
  "amount": "499.00",
  "payable_amount": "499.00",
  "currency": "INR",
  "utr": "412345678901",
  "paid_at": "2026-01-01T10:03:11+00:00",
  "paid_late": false
}

Headers X-Timestamp and X-Signature: sha256=<hex> are sent. The signature is HMAC-SHA256 of timestamp + "." + raw_body using your signing secret. Always verify it and reject old timestamps; webhooks can be delivered more than once, so make your handler idempotent on order_id.

import hmac, hashlib, time
from flask import Flask, request, abort

app = Flask(__name__)
SECRET = "whsec_..."          # from your dashboard

@app.post("/payment-webhook")
def webhook():
    ts  = request.headers.get("X-Timestamp", "")
    sig = request.headers.get("X-Signature", "")
    body = request.get_data()                       # raw bytes, not re-serialised JSON
    if not ts.isdigit() or abs(time.time() - int(ts)) > 300:
        abort(400)
    expected = "sha256=" + hmac.new(SECRET.encode(), ts.encode() + b"." + body,
                                    hashlib.sha256).hexdigest()
    if not hmac.compare_digest(sig, expected):
        abort(401)
    data = request.get_json()
    # TODO: if data["order_id"] not already fulfilled -> deliver the product
    return "ok"

Example: Telegram bot

import requests

def create_payment(user_id: int, amount: int):
    r = requests.post("{{ base }}/api/v1/orders",
        headers={"Authorization": "Bearer sk_live_xxx"},
        json={"amount": amount, "order_ref": f"tg{user_id}-premium"},
        timeout=10)
    r.raise_for_status()
    return r.json()["pay_url"]      # send this link to the user

Good to know

  • Confirmation depends on your bank/UPI app emailing you a credit alert, so timing follows that email.
  • A payment that arrives shortly after an order expired is still matched and flagged paid_late: true.
  • Money that arrives with no matching open amount shows as unmatched in your dashboard for manual handling.
  • Personal UPI accounts can have volume and use limits. Check your bank's and UPI app's terms before using one for business collections.
